Printer Connection Lab.

Does your PC put the printer in its local network range? Enter the printer’s subnet mask as well to check how it sees the PC.

The calculation runs in your browser. Your addresses stay on this page. To confirm that the print path works, try one test page from the PC.

Compare two addresses

Find the computer's local IPv4 address in Windows Settings or by running ipconfig. Find the printer's address on its settings screen or network status report. Use the address of the active Wi-Fi or Ethernet adapter. The gateway field names the router.

Use the active Wi-Fi or Ethernet adapter on the PC.

Select the mask shown by Windows for the same adapter.

Copy the subnet mask from the printer’s network report. Leave this blank if you only know the computer’s mask.

What this test tells you

  • With one mask you can tell whether the printer address falls in the PC’s subnet. The printer’s own view is still unknown.
  • With both masks you can see whether each device places the other inside its subnet. If they disagree, recheck the reported settings, especially a manual address left over from an old router.
  • It does not test reachability: this page cannot ping devices, see printer state, check spooler settings, or confirm working print protocols.
  • 169.254 on a device. A link-local address is useful only on its own link. Seeing one alone does not establish why it was assigned. IPv4 link-local specification.
Privacy & safety

Calculations happen inside your browser. No addresses are sent to Printer Resolve. Avoid publishing screenshots containing your address details or changing router security to “fix” a mismatch.

When the last number misleads

A PC at 192.168.1.126 and a printer at 192.168.1.129 share their first three numbers. Enter both with /25. The computer falls in 192.168.1.0/25 and the printer address in 192.168.1.128/25. With /24 the same pair falls in a single range.

Change the prefix in the calculator to reproduce both results. Use the actual mask from the active Windows adapter when checking your own devices. Microsoft’s subnetting explanation.

When only the PC sees a local address

Keep the PC at 192.168.1.126/24 and the printer at 192.168.1.129. With a printer mask of 255.255.255.0, each address is inside the other device’s subnet. Change only the printer mask to 255.255.255.128. The PC still includes .129, but the printer’s range now starts at .128, so it excludes .126.

Compare your two device reports before changing any settings. The Wi-Fi guide shows which fields to use on a Canon TR4700.

When the addresses are identical

A PC and a separate printer should have different IPv4 addresses on the same link. If the two entries match, first check you copied the printer’s IPv4 address, rather than its gateway or the PC’s entry twice. Two current device records with the same address warrant checking for an address conflict.

On a managed network, give the administrator the device names and time observed. How IPv4 address conflict detection works.

What to do after comparing

  1. Confirm that the printer is powered on and has a valid address on its network status page.
  2. Check the Windows printer entry at Settings → Bluetooth & devices → Printers & scanners.
  3. Compare the printer's current address with any manually configured TCP/IP port. Menu names vary by version and model.
  4. On a trusted local network, a Windows ping test may provide a clue, but no reply can mean ICMP is blocked — it does not automatically prove the printer is offline.
  5. Try one small test page after the lowest-risk corrective step.
